# 备份与同步

## 适用场景

你只有一份文件放在桌面上；网盘同步出一堆“冲突副本”；移动硬盘坏了；误删后回收站也清空了。

## 最小做法

### 先分清“同步”和“备份”

- **同步**：让多台设备看到同一份最新文件。它会把删除和改错也同步过去。
- **备份**：保留历史版本，出错后能恢复。它不应该被一次误删同步掉。

OneDrive、百度网盘、坚果云默认是同步，不是备份。不要把“开了同步”当成“有备份”。

### 3-2-1 原则

- **3** 份数据：原件 + 两份副本。
- **2** 种介质：本机硬盘 + 移动硬盘/另一台电脑。
- **1** 份异地：网盘、机房、家里。

学生版最小可行：

1. 本机工作目录。
2. 移动硬盘每周备份一次。
3. 重要文件另传一份到网盘或学校云盘。

### 目录分层

```text
work\            # 正在改的文件
archive\         # 已完成的版本，按日期打包
backup\          # 移动硬盘/网盘副本
```

- `work` 可以频繁改。
- `archive` 只新增，不覆盖；每周把完成的项目打成 `20261017_project.zip`。
- `backup` 用同步工具自动传，不手动拖。

### 恢复演练

备份不做恢复演练，等于没有备份。每学期至少做一次：

1. 从移动硬盘/网盘下载一个旧项目。
2. 解压到新目录，确认文件完整、能打开。
3. 记录恢复耗时和缺失文件。

## 进阶做法

- 用 `robocopy` 做增量备份：

```powershell
robocopy "D:\work" "E:\backup\work" /MIR /R:2 /W:5 /LOG+:E:\backup\robocopy.log
```

`/MIR` 会镜像删除，第一次用之前先确认目标目录没有别的东西。

- 用 Git 管理代码和文档，提交历史就是版本备份；大文件用 Git LFS 或单独存网盘。
- 用 7-Zip 打包时加密码和恢复记录，防止压缩包损坏。
- 给重要文件算哈希，恢复后校验：

```powershell
Get-FileHash .\submission.zip -Algorithm SHA256
```

## 常见坑

- 只开 OneDrive 同步，误删后同步删除，回收站也过期。
- 在同步目录里直接编辑 Office 文件，冲突副本越来越多。
- 把 Git 仓库放在 OneDrive 里，`.git` 被同步出冲突。
- 移动硬盘只插不备份，坏了才发现里面是唯一副本。
- 压缩包没有恢复记录，坏一个字节整个包打不开。
- 备份文件从不检查，真要用时发现是空的。

## 版本与时效

本文基于 Windows 11、PowerShell 7、OneDrive。不同网盘的冲突处理策略不同，但“同步不等于备份”这一点不变。
