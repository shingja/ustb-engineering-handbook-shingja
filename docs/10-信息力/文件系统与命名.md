# 文件系统与命名

## 适用场景

你经常找不到文件；同一个项目有 `最终版`、`最终版2`、`真的最终版`；换电脑后路径全断；队友发来的压缩包解压出一堆乱码目录。

## 最小做法

### 先定一个能长期用的目录结构

建议按“年份 / 项目 / 类别”三层，不要按软件分：

```text
D:\work\
├─ 2026\
│  ├─ competition-a\
│  │  ├─ 01_docs\        # 申报书、说明、会议记录
│  │  ├─ 02_design\      # 图纸、模型、仿真
│  │  ├─ 03_code\        # 代码、脚本、配置
│  │  ├─ 04_data\        # 原始数据、处理结果
│  │  ├─ 05_output\      # 提交包、导出 PDF、答辩 PPT
│  │  └─ 99_archive\     # 旧版本、废弃方案
│  └─ course-project\
└─ shared\
```

规则：

1. 目录名用英文、数字、下划线，避免空格和中文标点。
2. 文件名用 `日期_主题_版本`，例如 `20261017_申报书_v3.docx`。
3. 原始数据只读，处理结果另存，不覆盖原文件。
4. 最终提交物放 `05_output`，不要和过程文件混在一起。

### 命名规则

- 日期统一 `YYYYMMDD`，排序即时间线。
- 版本用 `v1`、`v2`、`v3`，不要用 `最终`、`改好的`、`新新新`。
- 一个人负责的文件加缩写后缀，例如 `_lt`，但公开前去掉。
- 避免 `()`、`[]`、`#`、`&`、空格；这些字符在命令行和压缩包里容易出问题。

### 路径

- 代码里用相对路径，不要写 `C:\Users\<user>\...`。
- 路径含空格时，命令行要加引号：`cd "D:\my work\project"`。
- Windows 路径分隔符 `\` 在 Python 字符串里要转义，或者用 `r"D:\work"`、`Path("D:/work")`。
- 跨平台项目统一用 `/`，Python 的 `pathlib` 会自动处理。

### 快捷方式与固定入口

- 桌面只放当前项目的快捷方式，不要放文件本体。
- 常用目录固定到资源管理器“快速访问”。
- 给项目根目录放一个 `README.md`，写清目录用途和负责人。

## 进阶做法

- 用 `Everything` 建索引，按文件名秒搜；用 `ripgrep` 搜内容。
- 用 `tree /F` 或 `Get-ChildItem -Recurse` 导出目录树，放进项目文档。
- 给每个项目加 `.gitignore`，把缓存、数据、输出排除。
- 大文件单独放 `04_data`，不要塞进 Git。
- 定期跑一次“空文件夹、重复文件、超大文件”清理。

## 常见坑

- 把文件全放桌面，重装系统或换电脑时找不到。
- 用“最终版”命名，三周后不知道哪个是真的最终。
- 目录名带空格，脚本批量处理时路径被截断。
- 在 OneDrive 同步目录里跑 Git，两个系统同时改文件，冲突不断。
- 解压时不看目录结构，直接覆盖了原文件。
- 把原始数据和处理结果混在一起，出错后无法回退。

## 自检清单

- [ ] 我有一个固定的项目根目录。
- [ ] 目录按“年份/项目/类别”分层。
- [ ] 文件名带日期和版本，不用“最终版”。
- [ ] 原始数据只读，处理结果另存。
- [ ] 代码里没有本机绝对路径。
- [ ] 项目根目录有 README 说明目录用途。
- [ ] 桌面只放快捷方式，不放文件本体。

## 版本与时效

本文基于 Windows 11 与 PowerShell 7。`Everything`、`ripgrep` 的具体版本会变，但“固定目录 + 日期版本 + 相对路径”的原则不变。
