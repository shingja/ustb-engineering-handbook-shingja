# 编码、后缀与压缩包

## 适用场景

打开中文文本是乱码；CSV 用 Excel 打开变成一堆问号；代码在 Windows 正常、到 Linux 就报错；压缩包解压后文件名全是 `锟斤拷`。

## 最小做法

### 先分清三个东西

- **字符编码**：文字怎么变成字节。常用 UTF-8；国内旧文件常见 GBK/GB2312。
- **换行符**：Windows 是 `CRLF`（`\r\n`），Linux/macOS 是 `LF`（`\n`）。
- **文件后缀**：只是文件名的一部分，不代表内容。把 `.xlsx` 改成 `.zip` 不会自动转换格式。

### 统一用 UTF-8

- 新建文本、代码、Markdown、CSV 一律 UTF-8。
- 不要用“UTF-8 with BOM”，除非目标软件明确要求；BOM 会让某些脚本第一行解析失败。
- Excel 打开 CSV 乱码时，用“数据 → 从文本/CSV”导入，手动选 UTF-8，而不是双击。

### 换行统一 LF

- Git 仓库加 `.gitattributes`：

```text
* text=auto eol=lf
```

- Windows 编辑器（VS Code、Typora）把默认换行设为 LF。
- 老项目如果全是 CRLF，不要一次性全改，先确认构建/脚本是否依赖。

### 压缩包

- 通用格式用 `.zip`；需要高压缩率用 `.7z`。
- 打包前先整理目录，不要在压缩包里放一层“新建文件夹”。
- 大压缩包加恢复记录（7-Zip 的 `-rr5%`），坏一个字节还能修。
- 加密压缩包用强密码，密码单独通过另一渠道发送，不要和压缩包放一起。

```powershell
7z a -t7z -mx=9 -mhe=on -rr5% project.7z .\project
```

## 进阶做法

- 用 VS Code 右下角编码切换，另存为 UTF-8。
- 用 Python 检测编码：

```python
from pathlib import Path
raw = Path("data.csv").read_bytes()
for enc in ("utf-8-sig", "utf-8", "gbk", "gb18030"):
    try:
        print(enc, raw.decode(enc)[:80])
        break
    except UnicodeDecodeError:
        continue
```

- 用 `file` 命令（Linux/macOS）或 `Format-Hex`（PowerShell）看文件头。
- 压缩包解压先看目录树，再决定是否覆盖。
- 给压缩包算 SHA-256，传输后校验。

## 常见坑

- 把后缀当格式：`.doc` 改 `.docx` 打不开。
- Excel 双击 CSV，默认按本地编码解析，中文乱码。
- UTF-8 BOM 导致 Python/Shell 第一行报“invalid character”。
- CRLF/LF 混用，Git diff 整个文件都变红。
- 压缩包里的文件名用 GBK，解压到 UTF-8 系统变乱码。
- 加密压缩包和密码放在同一封邮件里。
- 压缩包没有恢复记录，网盘传输损坏后无法修复。

## 自检清单

- [ ] 新文件统一 UTF-8，无 BOM。
- [ ] Git 仓库有 `.gitattributes` 统一 LF。
- [ ] CSV 用导入方式打开，确认编码。
- [ ] 压缩包目录结构干净，没有多余层级。
- [ ] 大压缩包有恢复记录。
- [ ] 加密压缩包密码单独发送。
- [ ] 重要压缩包有 SHA-256 校验。

## 版本与时效

本文基于 Windows 11、VS Code、7-Zip 24.x。编码标准不变，软件菜单会变；遇到乱码先确认编码，不要反复改后缀。
