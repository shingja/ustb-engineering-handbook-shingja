# 这本手册怎么用

## 适用场景

你刚进大学，或者第一次准备竞赛、第一次写申报书、第一次把代码交给别人。网上资料很多，但大多是零散的技巧，缺一条从“不会”到“能交付”的路径。

这本手册补的是这条路径。它不提供竞赛题库，不提供可直接提交的项目方案，也不替你决定做什么方向。它只讲三件事：

1. 工具怎么用，才能少返工。
2. 项目怎么推，才能按时交付。
3. 哪些线不能踩，才能不把成果和信用一起赔进去。

## 最小做法

先按你现在的阶段选一条路线，不要从头读到尾。

| 你的情况 | 建议路线 |
|---|---|
| 大一，刚接触大学学习 | 卷一“信息力” → 卷二“文档力” |
| 第一次参赛，不知道从哪下手 | 竞赛名录 → 卷四“竞赛值不值得参加” → 对应工具章节 |
| 已经是项目负责人 | 卷四的组队、项目管理、答辩、复盘 |
| 准备复盘/交接 | 卷四的复盘方法 |

每篇正文统一按六段写：

1. **适用场景**：什么时候该看这篇。
2. **最小做法**：今天就能照着做的步骤。
3. **进阶做法**：有余力再优化。
4. **常见坑**：别人已经踩过的。
5. **自检清单**：做完逐条打勾。
6. **版本与时效**：这篇基于什么版本、什么时候可能过时。

## 进阶做法

把手册当成“检查表”，不是“教科书”。

- 做项目时，只翻当前阶段对应的两三个章节。
- 做完一个阶段，回到自检清单逐条确认。
- 遇到手册没写的问题，先记录“场景、尝试、结果”，再决定要不要补进手册。

如果你要写自己的经验，建议用“决策—依据—结果—复盘”四段，而不是流水账。读者要的是判断方式，不是你做了多少事。

## 常见坑

- **从头读到尾**：内容按能力分卷，不是按课程顺序，通读容易失去重点。
- **把工具当目标**：学了一堆软件，但没做过一个完整交付。
- **照搬别人的项目**：方向每年都变，照搬既容易过时，也可能涉及别人的未公开内容。
- **忽略合规**：引用、AI 使用、隐私、版权，任何一项出问题，成果都可能作废。
- **不标注时效**：政策、软件界面、竞赛规则都会变，旧教程可能把人带偏。

## 自检清单

- [ ] 我知道自己现在该读哪一卷。
- [ ] 我读完一篇后，能说出“最小做法”的步骤。
- [ ] 我把当前项目的下一步写成了一个可执行动作。
- [ ] 我知道哪些内容不能公开、不能照搬。
- [ ] 我记录了所用软件的版本和参考日期。

## 版本与时效

本手册从 2026 年 10 月开始编写。软件操作以文中标注的版本为准；竞赛政策以学校当年发布的文件为准。发现内容过时，优先相信官方文件，并在 issue 中标注“章节 + 日期 + 变化点”。
