# 数据清洗与可复现

## 适用场景

你跑出一个结果，过两天自己都复现不了；队友用同一份数据跑出不同结果；答辩时被问“这个数怎么来的”。

## 最小做法

### 原始数据只读

```text
data/
├─ raw/          # 原始数据，永不修改
├─ interim/      # 清洗中间结果
└─ processed/    # 最终分析数据
```

- `raw` 只读，文件名带日期和来源。
- 清洗脚本放 `src/`，每一步可重跑。
- 处理结果写 `processed`，不覆盖原始数据。

### 清洗步骤写进脚本

不要在 Excel 里手动改 20 步，然后说“数据已经清洗好了”。把步骤写成代码：

```python
import pandas as pd
from pathlib import Path

raw = pd.read_csv("data/raw/20261017_measure.csv", encoding="utf-8")
df = (
    raw.rename(columns={"Time(s)": "time_s", "Value(mm)": "value_mm"})
       .dropna(subset=["time_s", "value_mm"])
       .query("0 <= value_mm <= 100")
       .sort_values("time_s")
)
Path("data/processed").mkdir(parents=True, exist_ok=True)
df.to_csv("data/processed/clean.csv", index=False)
```

每一步都写注释：为什么删、为什么截断、阈值从哪来。

### 固定随机种子

```python
import random
import numpy as np

random.seed(42)
np.random.seed(42)
```

深度学习还要设置框架种子；能固定就固定，不能固定的写清原因。

### 记录环境

- Python 版本、依赖版本。
- 操作系统、GPU/CPU。
- 数据文件哈希。
- 运行命令。

`复现清单.json` 示例：

```json
{
  "python": "3.11.9",
  "command": "python src/train.py --config configs/base.yaml",
  "data_sha256": "…",
  "seed": 42,
  "result": {"rmse": 0.97}
}
```

## 进阶做法

- 用 `pytest` 给清洗函数写测试：空值、越界、重复、类型错误。
- 用 `pydantic`/`pandera` 做数据校验。
- 用 `Makefile`/`just`/`invoke` 把“一条命令复现”固化。
- 用 `DVC` 或 Git LFS 管理大数据版本。
- 每次实验建一个 `runs/日期_配置/`，存日志、指标、图。

## 常见坑

- 手动改 Excel，原始数据被覆盖。
- 清洗规则只在脑子里，换人就跑偏。
- 删除缺失值时没记录删了多少、为什么。
- 随机种子没固定，结果每次不同。
- 只记录最终指标，不记录中间步骤。
- 环境和依赖没锁，换机器跑不起来。
- 图是截图，数据表找不到对应源。

## 自检清单

- [ ] 清洗步骤在脚本里，可重跑。

- [ ] 环境、依赖、命令、数据哈希有记录。

## 版本与时效

本文基于 Python 3.11、pandas 2.x。工具会变，但“原始数据只读 + 脚本化清洗 + 固定种子 + 复现清单”的原则不变。
