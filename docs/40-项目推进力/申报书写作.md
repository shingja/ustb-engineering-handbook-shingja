# 申报书写作

## 适用场景

你要写竞赛申报书、大创申请书、项目结题报告；内容很多，但不知道评委想看什么；写出来像说明书，没有重点。

## 最小做法

### 先写四块，再扩全文

1. **一句话摘要**：为谁、解决什么、做到什么程度。
2. **目标与指标**：可验证，不写“提升用户体验”。
3. **技术路线**：总体图 + 3-4 个关键模块。
4. **证据**：原型、测试、对比、用户反馈。

这四块写不清，后面扩写都是空话。

### 推荐结构

1. 项目摘要
2. 背景与问题（谁受影响、现有方案缺什么）
3. 目标与指标（量化、验收方式）
4. 方案与技术路线（总体图 + 模块）
5. 创新点（和现有方案比，具体改了什么）
6. 可行性（技术、时间、人员、经费）
7. 进度安排（里程碑 + 负责人 + 交付物）
8. 风险与应对（至少三条）
9. 经费预算（科目、单价、数量、用途）
10. 附录（图纸、代码说明、数据、参考文献）

### 证据链

每个结论后面跟证据：

- “效率提升 40%” → 测试条件、样本量、对比基线。
- “成本降低 30%” → BOM、报价、计算过程。
- “创新” → 专利/论文检索、方案对比表。
- “可行” → 原型照片、测试记录、团队成员能力。

没有证据的形容词，删掉或改成“设计目标”。

### 图与表

- 总体路线图：一页看懂。
- 模块图：接口清楚。
- 进度甘特图：里程碑和负责人。
- 对比表：现有方案 vs 你的方案。
- 测试数据表：条件、样本、指标、误差。

图注写清“图几、标题、数据来源”。

## 进阶做法

- 先写评分表对应的章节，再补过渡。
- 摘要最后写，控制在 300 字内。
- 每一节开头先给结论，再展开。
- 用“问题—方案—证据—边界”四段写每个创新点。
- 找非本专业的人读一遍，看能否看懂。
- 提交前做“陌生人视角”审查：假设你不认识作者，能否看懂。

## 常见坑

- 背景写三页，问题一句话带过。
- 创新点写“用了 AI/数字孪生”，没有对比。
- 指标不可验证：“显著提升”“大幅降低”。
- 技术路线图像流程图，没有接口和数据流。
- 预算写“其他”，没有明细。
- 风险和应对是“加强管理”“及时沟通”。
- 附录塞满，正文没有结论。
- 文档属性带真实姓名/单位，公开前没清理。

## 自检清单

- [ ] 摘要能一句话说清“谁、什么问题、做到什么程度”。
- [ ] 每个目标有可验证指标。
- [ ] 技术路线图一页看懂。
- [ ] 每个创新点有对比和证据。
- [ ] 进度表有负责人和交付物。
- [ ] 风险至少三条，有触发条件和应对。
- [ ] 预算有单价、数量、用途。
- [ ] 非本专业的人能读懂。
