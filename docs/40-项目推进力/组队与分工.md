# 组队与分工

## 适用场景

你要组队参加竞赛/做项目；队友很熟但没人干活；分工写成“大家一起做”；有人中途消失；署名和贡献说不清。

## 最小做法

### 先定角色，不先定人头

常见角色：

- **队长/协调**：定节奏、对外沟通、推进决策。
- **技术**：核心方案、代码/结构/实验。
- **文档**：申报书、报告、图表、提交包。
- **答辩**：PPT、讲稿、问答、现场演示。
- **后勤**：材料、采购、场地、报销、时间提醒。

一个人可以兼角色，但每个角色要有人负责。

### 分工到“交付物”

不要写“张三负责技术”，要写：

| 成员 | 负责模块 | 交付物 | 截止时间 | 备份人 |
|---|---|---|---|---|
| A | 结构设计 | 图纸 v1 + BOM | 10-30 | B |
| B | 控制 | 可运行代码 + 测试记录 | 11-10 | A |
| C | 文档 | 申报书 v1 + 图表 | 11-15 | D |

交付物要可验收：文件、演示、测试结果，不是“参与讨论”。

### 退出机制

组队第一天就谈：

- 有人退出，工作怎么交接？
- 已经做的工作怎么署名？
- 退出后还能不能使用共同成果？
- 什么情况下算“自动退出”（连续两周不响应）？

写进一份简单的组队约定，大家确认。

### 沟通节奏

- 每周一次 30 分钟例会：上周完成、本周计划、阻塞。
- 日常用群/文档异步沟通，重要决定留文字。
- 文档/代码集中在一个地方，不要散在聊天记录里。
- 截止前两周加一次“每日 10 分钟站会”。

## 进阶做法

- 用 GitHub Projects/飞书多维表格做任务板。
- 每周发周报，抄送队友/指导老师。
- 关键决策写“决策记录”：背景、选项、选择、理由。
- 设一个“红队”角色，专门挑方案漏洞。
- 给每个模块设备份人，避免单点故障。

## 常见坑

- 靠关系组队，不分工，最后一个人扛全部。
- 分工写“大家一起做”，没人负责。
- 不谈心退出，期末/赛前有人消失。
- 所有沟通在群里，文件过期/聊天记录找不到。
- 队长一个人做所有决定，其他人躺平。
- 署名按“谁嗓门大”，不按实际贡献。
- 指导老师直到提交前才看到东西。

## 自检清单

- [ ] 每个角色有人负责。
- [ ] 分工写到交付物和截止时间。
- [ ] 有备份人。
- [ ] 讨论过退出机制和署名规则。
- [ ] 每周有例会/周报。
- [ ] 重要决定有文字记录。
- [ ] 指导老师知道进度和风险。
