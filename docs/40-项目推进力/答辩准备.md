# 答辩准备

## 适用场景

材料交完了，马上要答辩；PPT 很多页，不知道讲什么；现场演示怕翻车；评委一问就慌。

## 最小做法

### 先定 3 个必须记住的结论

评委听完只记得 3 件事。先写下：

1. 我们解决了什么问题。
2. 我们做到了什么程度（指标）。
3. 我们的证据是什么。

所有 PPT 页都围绕这 3 件事。

### PPT 结构（10-15 分钟）

1. 封面：项目名 + 一句话定位。
2. 问题：谁、什么场景、现有方案缺什么。
3. 目标：1-3 个可验证指标。
4. 方案：总体路线图 + 关键模块。
5. 证据：原型/测试/对比。
6. 分工与进度：谁做了什么，下一步。
7. 风险与边界：至少三条。
8. 结束页：结论 + 联系方式。

每页一个结论，标题写结论，不写栏目名。

### 讲稿

- 每页 2-4 句口语，不写逐字稿。
- 开头 30 秒说清“做了什么、结果如何”。
- 时间分配：问题 20%，方案 30%，证据 35%，收尾 15%。
- 至少完整试讲两遍，掐表。
- 准备一个 3 分钟版本，防止临时压缩时间。

### 问答

准备 8 个问题：

- 和现有方案比，优势在哪？
- 关键指标怎么测的？误差多大？
- 如果核心模块失败，怎么办？
- 成本/周期/可制造性如何？
- 哪些是你们做的，哪些是现成工具？
- 创新点具体在哪？有对比吗？
- 数据/样本够不够？
- 下一步怎么做？

回答：先结论，再证据，最后边界。不会就说“这一点还没验证”。

### 演示风险

- 现场演示准备：本地文件 + 录屏 + 备用设备。
- 不依赖网络；必须联网的，准备热点。
- 演示前重启设备，关掉通知/弹窗。
- 准备“失败话术”：如果卡住，切录屏，继续说。

## 进阶做法

- 用母版统一字体、颜色、页码。
- 关键页加备份页，问答时跳转。
- 用演讲者视图看备注，但不照读。
- 找同学当“假评委”提问。
- 答辩前一天去场地试投影/音响。
- 准备一份一页纸的“核心数据卡”。

## 常见坑

- 第一页放 20 个项目背景，评委不知道你要讲什么。
- 每页字太多，字号小于 18pt。
- 动画过多，翻页卡顿。
- 只有方案，没有证据。
- 现场演示依赖网络/实验室设备。
- 回答问题超时，挤掉后面内容。
- 结束页只有“谢谢聆听”，没有结论。

## 自检清单

- [ ] 我能说出 3 个必须记住的结论。
- [ ] 每页标题是一个结论。
- [ ] 一页最多一个图 + 三条要点。
- [ ] 每个结论有证据或标注“待验证”。
- [ ] 讲稿能在规定时间内讲完。
- [ ] 试讲至少两遍，掐表。
- [ ] 准备了 8 个问答。
- [ ] 演示有录屏和本地备份。
