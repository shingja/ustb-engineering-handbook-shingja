# 团队协作与冲突

## 适用场景

你要组队做竞赛/项目；队友之间出现分歧；有人不干活；有人中途退出；署名谈不拢。

## 我见过的有效做法

### 1. 先小人后君子

组队第一天就把丑话说清：

- 谁负责什么，交付物是什么。
- 每周投入多少小时。
- 有人退出怎么交接。
- 署名按什么排。

写成一页纸，大家确认。不是不信任，是避免后面靠猜。

### 2. 分工到“可验收”

“你负责文档”不如“你负责申报书第 1-5 节，11 月 10 日前交 v1，包含 3 张图”。可验收，才知道有没有完成。

### 3. 每周一次短会

30 分钟，三个问题：

- 上周完成了什么？
- 这周做什么？
- 有什么阻塞？

不用开长会，但要固定。很多问题不是难，是没人提。

### 4. 重要决定留文字

群里说“那就这么定了”，过两周没人记得。把决定、理由、待办写进文档/issue，谁都能回看。

### 5. 冲突先对事实

队友争执时，先对：

- 交付物在哪？
- 什么时候交的？
- 谁在用？
- 证据是什么？

对完事实，很多情绪会降下来。对完还解决不了，再找老师/学长。

## 我踩过的坑

### 1. 靠关系组队

关系好不等于能干活。没有分工和退出机制，最后一个人扛，其他人不好意思说，也不敢退出。

### 2. 队长包办

队长什么都做，其他人插不上手，最后队长累垮，队友也没成长。队长应该做的是定节奏、清阻塞，不是抢所有活。

### 3. 不说不满

有人对分工不满，但不说，最后用“消失”表达。定期一对一聊 5 分钟，比事后补救有用。

### 4. 署名最后谈

项目做完才谈署名，谁都觉得自己的贡献最大。应该在中期就确认顺序，按交付物/角色，不按感觉。

### 5. 退出没有交接

有人退出，代码/文档在他电脑里，其他人接不上。退出机制要写清：交接什么、交给谁、什么时候。

## 如果重来一次

1. 组队先写一页约定：分工、投入、退出、署名。
2. 每周短会 + 周报，阻塞不过夜。
3. 重要决定留文字。
4. 中期确认署名顺序。
5. 队长做“清障”，不做“包办”。

## 自检清单

- [ ] 我们有一页组队约定。
- [ ] 分工写到交付物和截止时间。
- [ ] 每周有短会/周报。
- [ ] 重要决定有文字记录。
- [ ] 中期确认过署名顺序。
- [ ] 退出机制写清。
- [ ] 有人负责对外沟通。
