# 失败复盘

## 适用场景

你参加了一个比赛但没获奖；项目做到一半停了；答辩现场翻车；队友退出。你想知道这些经历到底有什么用。

## 我经历过的几类失败

### 1. 没获奖

原因通常不是“评委不懂”，而是：

- 题目太大，没做完。
- 有方案，没证据。
- 材料格式/提交出问题。
- 答辩讲不清重点。

没获奖不等于白做。把交付物、测试记录、复盘留下来，下一个项目能直接用。

### 2. 做到一半停了

常见原因：

- 关键模块卡住，没有备选方案。
- 队友退出，没人接手。
- 时间被课程/考试挤掉。
- 方向本身不成立。

停下来不一定是错，但要写清“为什么停、停在哪、还有什么能用”。

### 3. 现场翻车

演示失败、PPT 打不开、设备没电、网络断了。后来做的改变：

- 演示准备本地文件 + 录屏 + 备用设备。
- 提前去场地试。
- 准备“失败话术”，卡住就切录屏。
- 关键数据背下来，不依赖屏幕。

### 4. 队友/署名纠纷

经历过一次就明白：组队第一天要把分工、退出、署名写清。不是不信任，是保护所有人。

## 失败后怎么复盘

### 1. 先写事实

- 目标是什么？
- 实际做到什么？
- 哪个节点开始偏？
- 证据是什么？

不写“大家都很努力”，写交付物和时间线。

### 2. 找可控原因

把原因分两类：

- **可控**：选题、分工、进度、测试、材料。
- **不可控**：设备故障、政策变化、评委偏好。

复盘重点放在可控项。

### 3. 提炼一条“下次提前做什么”

不要写 20 条，写 1-3 条能执行的：

- 选题先压到一句话。
- 关键模块准备备选方案。
- 官方截止前 3 天内部截止。
- 答辩前完整试讲两遍。

### 4. 保留资产

- 代码/图纸/测试数据。
- 文档/PPT/答辩稿。
- 供应商/加工渠道。
- 复盘文档。

## 失败的价值

失败不会自动变成经验，复盘才会。

- 它告诉你自己的边界：哪些事能做、哪些事需要别人。
- 它告诉你流程的漏洞：哪个节点最容易出问题。
- 它让你在下一个项目里更快判断“这个方向行不行”。

## 版本与时效

本文是个人经验。比赛结果受多种因素影响，复盘是为了下一次做得更好，不是为了给自己下结论。
