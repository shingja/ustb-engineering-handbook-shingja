# Markdown 与编辑器

## 适用场景

你要写实验记录、项目文档、博客、README，或者把 Word 里的内容整理成可版本管理的文本。

## 最小做法

### 常用语法

```markdown
# 一级标题
## 二级标题

**加粗**  *斜体*  `行内代码`

- 无序列表
1. 有序列表

> 引用

[链接](https://example.com)
![图片](assets/demo.png)

| 列 1 | 列 2 |
|---|---|
| A | B |

```python
print("hello")
```
```

规则：

- 标题层级不要跳级：`#` → `##` → `###`。
- 代码块标语言，方便高亮。
- 图片放 `assets/` 或同目录，用相对路径。
- 文件名用英文/数字/短横线，避免空格。
- 一段只讲一件事，长段落拆成列表。

### 编辑器选择

- **VS Code**：适合代码 + Markdown + Git，插件多，免费。
- **Typora**：所见即所得，适合纯写作；注意许可证。
- **Obsidian/Logseq**：适合双链笔记，不适合当代码仓库。
- **在线编辑器**：方便协作，但隐私和导出格式要确认。

### VS Code 最小配置

```json
{
  "files.encoding": "utf8",
  "files.eol": "\n",
  "editor.wordWrap": "on",
  "markdown.preview.breaks": true,
  "markdownlint.enabled": true
}
```

推荐插件：Markdown All in One、markdownlint、Code Spell Checker、GitLens。

### 导出

- 导出 PDF：用 VS Code 的 Markdown PDF 插件，或先转 HTML 再打印。
- 导出 Word：用 Pandoc；没有 LaTeX 时用 `--reference-doc` 套模板。
- 导出前检查：图片路径、代码块换行、表格宽度、中文字体。

## 进阶做法

- 用 frontmatter 记录标题、日期、标签：

```yaml
---
title: 实验记录
date: 2026-10-17
tags: [experiment, motor]
---
```

- 用 `<!-- comment -->` 写不渲染的备注。
- 用 Mermaid 画流程图，文本可 diff。
- 用 Git 管理文档，提交信息写“改了什么”。
- 用 `markdownlint` 统一格式，减少无意义 diff。

## 常见坑

- 图片用绝对路径，换电脑全裂。
- 标题层级乱跳，目录生成错。
- 代码块不标语言，高亮和复制都难受。
- 表格用空格对齐，渲染后错位。
- 直接粘贴网页内容，带入隐藏格式。
- 中文文件名在部分静态站点/命令行下编码出错。
- 导出 PDF 时字体缺失，中文变方块。

## 自检清单

- [ ] 图片用相对路径，文件存在。

## 版本与时效

本文基于 VS Code 1.141、Typora 1.8。Markdown 语法稳定，编辑器和插件会变；导出前以实际渲染结果为准。
