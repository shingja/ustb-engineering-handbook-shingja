# 文档协作与版本

## 适用场景

三个人改同一份申报书；队友发来“最终版”和“最终版_改”；改完不知道谁动了哪一段；提交前合并出一堆冲突。

## 最小做法

### 先定“唯一主文件”

- 指定一个人维护主文件，其他人提交修改建议。
- 主文件放共享目录/仓库，文件名固定，不加“最终版”。
- 每次修改前先拉最新版，改完立刻回传。

### Word 修订

1. 审阅 → 修订，开启 tracked changes。
2. 改完保存，文件名带日期和修改人：`20261017_申报书_张三修订.docx`。
3. 主文件维护者逐条接受/拒绝，不要整篇接受。
4. 合并后删除批注、隐藏个人信息。

### 在线文档

- 腾讯文档/飞书/石墨适合实时协作，但导出格式可能变。
- 定好“谁负责哪一节”，避免多人同时改同一段。
- 用评论而不是直接改别人段落。
- 重要版本导出 PDF 存档。

### Git 管文档

适合 Markdown/代码/配置，不适合二进制 Word 的频繁合并。

```powershell
git pull
git add docs/
git commit -m "docs: update budget section"
git push
```

规则：

- 一次提交只改一个主题。
- 提交信息写“改了什么”。
- 二进制文件（docx/pptx）不要多人同时改；用“谁改谁提交”。
- 大文件用网盘，不进 Git。

## 进阶做法

- 用 `docs/` 分目录：`01_申报书/`、`02_附件/`、`03_答辩/`。
- 用 `CHANGELOG.md` 记录每次提交给谁、改了什么。
- 用分支：`draft/申报书`、`final/提交版`。
- 用 Issue 跟踪待改项，改完关闭。
- 用 PDF 作为对外唯一版本，Word 只作编辑源。

## 常见坑

- 多人同时改同一个 docx，最后只能手动合并。
- 文件名“最终版”满天飞，不知道哪个是提交版。
- 在线文档导出后格式错乱。
- Git 里提交大二进制文件，仓库爆炸。
- 修订没接受，打印出来带删除线。
- 批注里写了队友/老师信息，公开前没清理。
- 没有版本记录，出问题无法回退。

## 自检清单

- [ ] 有唯一主文件和维护人。
- [ ] 修改前先拉最新版。
- [ ] Word 修订逐条处理，批注删除。
- [ ] 文件名带日期/修改人，不用“最终版”。
- [ ] 对外版本统一导出 PDF。
- [ ] Git 提交信息可读，二进制文件不频繁合并。
- [ ] 有 CHANGELOG 或提交记录。

## 版本与时效

本文基于 Word 2024、腾讯文档/飞书、Git 2.55。协作工具会变，但“唯一主文件 + 明确分工 + 版本记录”的原则不变。
