# PPT 答辩叙事

## 适用场景

你要做课程汇报、竞赛答辩、项目结题。内容很多，时间很短，评委只看几分钟。

## 最小做法

### 先定叙事，不先找模板

答辩不是“把做过的事全放上去”，而是回答四个问题：

1. 你要解决什么问题？
2. 为什么你的方案值得做？
3. 你怎么证明它有效？
4. 下一步是什么？

推荐结构（10-15 分钟）：

1. 封面：项目名 + 一句话定位。
2. 问题：场景、痛点、现有方案缺什么。
3. 目标：可验证的指标。
4. 方案：总体路线图 + 关键模块。
5. 证据：实验/原型/对比结果。
6. 分工与进度：谁做了什么，下一步。
7. 风险与应对：至少三条。
8. 结束页：结论 + 联系方式。

### 每页只讲一个结论

- 标题写结论，不写“方案介绍”“实验结果”这种空标题。
- 一页最多一个图 + 三条要点。
- 图放大，字少；评委看不清的图等于没放。
- 关键数字加粗，单位写清。

### 证据链

每个结论后面跟一个证据：

- 实验数据：样本量、条件、误差。
- 对比：和谁比、指标是什么、提升多少。
- 原型：照片/视频/现场演示。
- 失败案例：边界条件、未达标项，主动说。

没有证据的“创新点”，改成“设计思路”或删掉。

### 讲稿

- 每页写 2-4 句口语，不写逐字稿。
- 开头 30 秒说清“我们做了什么、结果如何”。
- 时间分配：问题 20%，方案 30%，证据 35%，收尾 15%。
- 至少完整试讲两遍，掐表。

### 问答

提前准备 5 个问题：

- 你的方案和现有方案比，优势在哪？
- 关键指标怎么测的？误差多大？
- 如果某个模块失败，怎么办？
- 成本/周期/可制造性如何？
- 哪些是你们做的，哪些是现成工具？

回答原则：先结论，再证据，最后边界。不会就说“这一点还没验证”。

## 进阶做法

- 用母版统一字体、颜色、页码。
- 图表用矢量图或高分辨率 PNG，不要截图。
- 关键页加“备份页”，放在最后，问答时跳转。
- 现场演示准备录屏 + 本地文件 + 备用设备。
- 用演讲者视图看备注，但不要照读。

## 常见坑

- 第一页放 20 个项目背景，评委不知道你要讲什么。
- 每页字太多，字号小于 18pt。
- 动画过多，翻页卡顿。
- 只有方案，没有证据。
- 现场演示依赖网络，断网就讲不下去。
- 回答问题超时，挤掉后面的内容。
- 结束页写“谢谢聆听”，没有结论。

## 自检清单

- [ ] 每页标题是一个结论，不是栏目名。
- [ ] 一页最多一个图 + 三条要点。
- [ ] 每个结论有证据或明确标注“待验证”。
- [ ] 讲稿能在规定时间内讲完。
- [ ] 试讲至少两遍，掐表。
- [ ] 准备了 5 个问答。
- [ ] 演示有录屏和本地备份。
- [ ] 结束页有结论和联系方式。

## 版本与时效

本文基于 PowerPoint 2024。模板和动画会变，但“问题—方案—证据—边界”的叙事结构不变。
